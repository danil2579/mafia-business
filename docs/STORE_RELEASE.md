# Подготовка Steam и App Store

Веб/PWA‑версия уже устанавливается на ноутбуки и телефоны. Публикация в магазинах — отдельный завершающий этап, который требует внешних аккаунтов, домена и подписей.

## Общая обязательная инфраструктура

1. Развернуть `server.js` на постоянном HTTPS‑домене.
2. Подключить постоянную базу данных для аккаунтов и Redis/adapter для комнат перед запуском нескольких серверных процессов.
3. Настроить мониторинг доступности `/api/health`, резервные копии, журналирование без персональных данных и политику конфиденциальности.
4. Провести нагрузочное тестирование с целевым числом одновременных комнат.

## Steam

Для Steam нужен нативный desktop‑контейнер (обычно Electron/Tauri), который открывает production‑клиент, корректно обрабатывает deep links, fullscreen, выход и обновления. Затем нужны:

- аккаунт Steamworks и оплаченный app credit;
- Windows/macOS/Linux билды из соответствующих toolchain;
- иконки, capsule art, скриншоты, описание и возрастной рейтинг;
- Steamworks SDK только для нужных функций (overlay, invites, achievements, cloud saves);
- подпись, depot/upload через SteamPipe и проверка review build.

Без production URL и Steamworks App ID нельзя выпустить рабочий сетевой Steam‑билд: локальные экземпляры приложения не разделяют комнаты.

## Apple App Store

Для iPhone/iPad нужен Apple Developer Program, Bundle ID, сертификаты и provisioning profiles. Практичный путь — Capacitor‑контейнер вокруг production PWA с нативными состояниями сети, safe area, privacy manifest и корректными ссылками на поддержку/политику конфиденциальности.

Apple может отклонить простой web wrapper, поэтому до отправки стоит добавить нативную ценность: Game Center/SharePlay, push‑приглашения, haptics или полноценный offline tutorial. Финальная сборка и подпись выполняются через Xcode на macOS, затем TestFlight и App Review.

## Что нельзя автоматизировать без владельца продукта

- принять юридические соглашения и возрастной рейтинг;
- приобрести/подтвердить аккаунты разработчика;
- выбрать production‑домен и политику хранения данных;
- выпустить сертификаты и подписать магазинные бинарники;
- отправить приложение на модерацию от имени владельца.
